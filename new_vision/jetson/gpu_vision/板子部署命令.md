# Orin Nano 板子部署与检测命令

从空白板子到跑起来。按顺序执行，别跳步。

## 1. 性能档位 ⚠️ 先读这段再动手

```bash
sudo nvpmodel -q --verbose      # 查当前档位（-q 是 query，-p 只解析配置文件）
sudo nvpmodel -q                # 简版
grep "POWER_MODEL ID" /etc/nvpmodel.conf   # 列出所有可用档位
```

**出厂默认就是 15W，且 CPU 能跑满 1.728GHz —— 先用默认档测帧率，数字通常就够。**

### ⚠️ `nvpmodel -m 0`（MAXN）有掉盘风险，谨慎使用

实测踩过：执行 `sudo nvpmodel -m 0` 后重启，**M.2 NVMe 从 PCIe 上完全消失**
（UEFI `pci -b` 里只剩 NVIDIA 自己的桥和网卡），系统再也进不去，直接落到
UEFI Shell。

原因是 MAXN 档拉满 SoC 功耗后，PCIe 信号裕量变小，**M.2 接触临界时就会掉**。
换了插槽后恢复。

**如果一定要试**：
- 确认电源适配器 ≥ 25W（Orin Nano Super 官方要求）
- M.2 固定螺丝拧紧，插槽弹片状态良好
- 改完**完全断电**（拔电源适配器等 30 秒），不要软重启

**掉盘了怎么救**（按顺序）：
1. 完全断电 30 秒后上电
2. 换一个 M.2 插槽 / 重新插拔 M.2
3. 开机按 ESC 进 UEFI → `Device Manager` → `NVIDIA Configuration` → `Reset Settings`
   （只重置固件配置，**不动硬盘数据**）

### 替代方案：`jetson_clocks`（安全、可逆）

```bash
sudo jetson_clocks          # 运行时锁最高频，不写 QSPI，重启即恢复
sudo jetson_clocks --show   # 查看当前频率
```

**它不持久化** —— 出问题重启就回到原样，不会像 `nvpmodel` 那样把 NVMe 搞掉。
想提性能优先用它。

## 4. Python 环境

```bash
python3 -m venv ~/robocup-venv --system-site-packages
source ~/robocup-venv/bin/activate
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
pip install "numpy<=1.26.4"
pip install pyserial
python -c "import cv2; print('cv2', cv2.__version__, cv2.__file__)"
```

**`--system-site-packages` 不能省** —— 板子预装的 OpenCV（apt 的 `python3-opencv`）
在系统 Python 下，普通 venv 是隔离的，`import cv2` 会直接报
`ModuleNotFoundError: No module named 'cv2'`。

最后那行要能打印出 cv2 版本和路径才算成功。如果报错，说明板子没装系统 OpenCV，
补一句 `sudo apt install -y python3-opencv` 重试；或者改用 pip 装
`pip install "opencv-python>=4.8,<5"`（PyPI 从 4.10 起有 aarch64 wheel）。

`numpy<=1.26.4` 是硬约束 —— 系统那份 OpenCV 按 numpy 1.x 编译。

```
cd ~/Robocup/jetson/gpu_vision

# 2. 相机输出格式 —— 决定 MJPEG 硬解值不值

python -c "import cv2; print('threads:', cv2.getNumThreads())"

python -c "
import cv2, numpy as np, time
g = (np.random.rand(400,320)*255).astype(np.uint8)
for name, shape in [('ELLIPSE', cv2.MORPH_ELLIPSE), ('RECT   ', cv2.MORPH_RECT)]:
  k = cv2.getStructuringElement(shape, (31,31))
  cv2.morphologyEx(g, cv2.MORPH_BLACKHAT, k)
  t = time.time()
  for _ in range(10):
    cv2.morphologyEx(g, cv2.MORPH_BLACKHAT, k)
  print(f'{name} 31x31 on 320x400: {(time.time()-t)/10*1000:6.1f} ms')
  "
```

## 9. 判据

| 全链 FPS | 动作 |
|---|---|
| ≥ 15 | **够了，收工**。控制环只有 10Hz |
| 10–15 | 降分辨率：加 `--width-640`（代价：红条测距精度减半） |
| < 10 | 上面那条 + 考虑编译带 CUDA 的 OpenCV（见 README，CUDA 13.2 上需 cudev 补丁） |

## 附：环境变量一览

`run_robot.py` 及其依赖（`shape_detector.py`、`camera_config.py`）自定义的全部环境变量。
一律是 `os.environ.get("名字", 默认值)`，**不设就用默认值**，不会报错。

### 相机

默认取 `config/cameras.json` 的 `active` 段，下面这些 env 可逐项覆盖它。

| 变量 | 默认 | 说明 |
|---|---|---|
| `CAMERA_PROFILE` | `cameras.json` 的 `active` | 切换到别的配置段 |
| `CAM_IDX` | `cameras.json` 的 `index`（0） | 相机索引，也可用 `--cam N` |
| `CAM_HEIGHT_CM` | `mount_height_cm`（40.0） | 相机安装高度 cm |
| `CAM_PITCH_DEG` | `pitch_deg`（45.0） | 相机俯角 |
| `CAM_VFOV_DEG` | `vfov_deg`（56.2） | 垂直视场角 |

### 步态 / 路线

| 变量 | 默认 | 说明 |
|---|---|---|
| `STEP_LEN_CM` | 8.0 | 机器人一步前进距离 cm |
| `PREVIEW_GAIN` | 1.0 | 一步前瞻增益 |
| `ROUTE_DEADBAND_CM` | 1.5 | 偏差 ≤ 此值 → 发 GO |
| `ROUTE_LEFT_THRESH_CM` | 2.0 | 偏差 < 负此值 → 发 LEFT，否则 SLIGHT_LEFT |

### PID

| 变量 | 默认 |
|---|---|
| `JETSON_PID_STRAIGHT_KP` / `JETSON_PID_STRAIGHT_KI` / `JETSON_PID_STRAIGHT_KD` | 0.83 / 0.004 / 0.095 |
| `JETSON_PID_CURVE_KP` / `JETSON_PID_CURVE_KI` / `JETSON_PID_CURVE_KD` | 0.78 / 0.002 / 0.16 |
| `JETSON_PID_I_CLAMP` | 60.0 |
| `JETSON_PID_DT` | 0.033 |

### 丢线恢复

| 变量 | 默认 | 说明 |
|---|---|---|
| `LOST_HOLD_FRAMES` | 6 | 丢线后保持历史转向的帧数 |
| `LOST_SEARCH_TURN` | 11.0 | 搜索阶段转向量 |

### 串口

| 变量 | 默认 | 说明 |
|---|---|---|
| `SERIAL_PORT` | 空 = 自动探测 | Windows 扫 COM1-9，Linux 扫 `/dev/ttyUSB*` `/dev/ttyACM*` |
| `SERIAL_BAUD` | 115200 | |

### 协议 / 运行

| 变量 | 默认 | 说明 |
|---|---|---|
| `CTRL_HZ` | 0 = 逐帧发 | >0 时限速（如 `12` 限回协议 8~12Hz），0 表示每帧一条 |
| `REAL_CAR_MAX_SEC` | 0 = 不限时 | 限时运行，到点自动退出 |

LINE_CTRL 默认逐帧发送，频率 = 主循环帧率（本地 ~23Hz，板子受 CPU 限制约 6~7Hz）；
HEARTBEAT 固定 10Hz。

### 图卡识别

| 变量 | 默认 | 说明 |
|---|---|---|
| `SHAPE_MAX_DIST_CM` | 80.0 | 图卡最大识别距离 cm |

### 用法示例

```bash
# 多个变量一起传（只对本次运行生效）
STEP_LEN_CM=9.5 SERIAL_PORT=/dev/ttyUSB0 python run_robot.py --headless --no-serial
```

**实车必按实际改的**：
- `CAM_HEIGHT_CM` / `CAM_PITCH_DEG` —— 相机装好后量出来的值（或直接改 `config/cameras.json`）
- `STEP_LEN_CM` —— 机器人实际一步走多远

其余用默认值即可跑通。

> 测试车控制器 `jetson/run_real_car.py` 另有一套变量（`REAL_CAR_SPEED`、`JETSON_STEER_SAT` 等），
> 见该文件头部。

## 附：装 zsh + oh-my-zsh（可选）

只是终端好用，跟部署无关。整块复制粘贴即可：

```bash
# 1. 装 zsh + 补全插件（apt 自带，不碰 GitHub）
sudo apt update
sudo apt install -y zsh git curl zsh-autosuggestions

# 2. 备份已有配置（没有会报 not found，无害）
[ -f ~/.zshrc ] && cp ~/.zshrc ~/.zshrc.bak

# 3. 装 oh-my-zsh —— 先试 Gitee 镜像，连不上自动换 GitHub
if ! git clone --depth 1 https://gitee.com/mirrors/oh-my-zsh.git ~/.oh-my-zsh; then
    rm -rf ~/.oh-my-zsh
    git clone --depth 1 https://github.com/ohmyzsh/ohmyzsh.git ~/.oh-my-zsh
fi

# 4. 生成配置 + 挂上历史建议插件
cp ~/.oh-my-zsh/templates/zshrc.zsh-template ~/.zshrc
echo 'source /usr/share/zsh-autosuggestions/zsh-autosuggestions.zsh' >> ~/.zshrc

# 5. 设为默认 shell（会提示输密码）
chsh -s $(which zsh)
```

然后 `exec zsh` 立即生效，不用重开终端。主题保持默认（robbyrussell）。

**装完什么样算成功**：提示符变成彩色（不再是灰扑扑的 `$`），敲半个命令会出现
灰色历史建议、按 `→` 接受，按 Tab 能补全命令和路径。

装完得到两个补全：**Tab 补全**（oh-my-zsh 自带）+ **历史建议**（敲字时灰字提示以前打过的命令，按 `→` 接受）。

注意：

- `zsh-autosuggestions` 是 apt 装的，落在 `/usr/share/` 下，只能 `source` 挂上去，
  不能写进 `plugins=()`（oh-my-zsh 找不到它）
- `cp` 会覆盖已有的 `~/.zshrc`，新板子无所谓，上面有配置的话先备份
- **别装 `zsh-syntax-highlighting`**：它必须排在插件列表最后加载，跟手动 source 的方式容易踩顺序坑

### 装不上 / 装完不对怎么办

**两个源都连不上**（`git clone` 卡住或报 connection reset）
在能上网的电脑上打开 `https://github.com/ohmyzsh/ohmyzsh/archive/refs/heads/master.zip`，
下载解压后把文件夹改名成 `.oh-my-zsh`，拷到板子的 `~/` 下，再从上面**第 4 步**继续。

**`chsh` 报 `Authentication failure` 或改了没生效**
```bash
grep zsh /etc/shells            # zsh 不在列表里的话，chsh 会拒绝
echo $(which zsh) | sudo tee -a /etc/shells
chsh -s $(which zsh)
```
`chsh` 改的是登录 shell，**要退出 SSH 重连才生效**（`exec zsh` 只是临时切当前窗口）。

**新 shell 一直报错、进不去**
在 bash 里跑 `zsh -f`（跳过所有配置文件启动）定位问题：
- 能起来 → 是 `.zshrc` 的问题，`mv ~/.zshrc.bak ~/.zshrc` 恢复备份，
  或者直接删掉 `~/.zshrc` 重新跑第 4 步
- 还是起不来 → `chsh -s /bin/bash` 先切回 bash，再看 zsh 本身装没装好

## 附：怎么撤销

上面每一步都能单独回退，代码不受影响。

### 卸掉 torch

图卡识别走纯 CV 规则法，不需要 torch（它有几个 GB）。

```bash
source ~/robocup-venv/bin/activate
pip uninstall -y torch
```

确认卸干净：

```bash
pip list | grep -i -E "torch|nvidia"
```

**更彻底的清法**：torch 体积大、拖的依赖多，直接重建环境最快：

```bash
deactivate
rm -rf ~/robocup-venv
python3 -m venv ~/robocup-venv --system-site-packages
source ~/robocup-venv/bin/activate
pip install "numpy<=1.26.4" pyserial
python -c "import cv2; print('cv2', cv2.__version__)"
```

`rm -rf ~/robocup-venv` 只删环境，`~/Robocup` 里的代码一根毛都不少 —— 这也是 venv 存在的意义。

### 撤销 oh-my-zsh，换回 bash

```bash
chsh -s $(which bash)                        # 重登录生效
rm -rf ~/.oh-my-zsh ~/.zshrc ~/.zshrc.bak    # 删配置（含装之前的备份）
sudo apt remove --purge -y zsh zsh-autosuggestions
```

### 恢复默认功耗档

`jetson_clocks` 重启就失效。`nvpmodel` 是持久的，要手动换回去：

```bash
grep "POWER_MODEL ID" /etc/nvpmodel.conf   # 先看档位编号和名字
sudo nvpmodel -q --verbose                 # 看当前是哪个档
sudo nvpmodel -m 0                         # 换成你要的档（换成 15W 的 ID）
```

⚠️ **换档后务必完全断电重启**（拔电源适配器等 30 秒），不要软重启 ——
见第 1 节的掉盘说明。

### 取消串口免 sudo

```bash
sudo deluser $USER dialout         # 重登录生效
```

### 确认代码没被动过

环境怎么折腾都不碰代码，随时可以核对：sudo

```bash
cd ~/Robocup && git status
```
