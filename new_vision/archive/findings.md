## 赛事规则 PDF — 已入库：`rule.pdf`（仓库根目录）

来源：**《工程竞技类机器人赛项人形竞技全能项目竞赛规则》**（2025 年 2 月版，中国机器人大赛暨 RoboCup 中国赛）。  
以下摘录自 PDF 文本层（**非臆造**）；页码以 PDF 阅读器为准，章节以原文「六、七」等为准。

### 与视觉 / 二维码直接相关的官方表述（摘录）

**背景（第一节要义）**  
机器人须用传感器识别**赛道、二维码、障碍物**等，并实现闭环控制。

**6.2 比赛器材说明 —（一）二维码**

1. 二维码为数字 **1～6**，对应 6 个规定动作序号；可白纸打印，尺寸为 **5 cm×5 cm** 正方形；图案见附录。  
2. 赛道中摆放 **3 个**二维码：**第 1 个**在起跑线**前方 30 cm**；**第 2 个**在**直道中间**；**第 3 个**在**弯道中间**（见图 1）。  
3. 赛前由队员从 1～6 **随机抽取**二维码；赛时可用透明胶带粘贴在场地图上。

**7.2 比赛流程 — 二维码抽签**  
参赛队员从数字 1～6 的**六张二维码中抽取 3 张**作为本场动作二维码。

**7.3 比赛任务 —（一）任务 2**  
行进中须识别 **3 处**二维码并完成对应动作：

| 序号 | 动作要求 |
|------|-----------|
| 1 | 举起左手，维持 **3 s 以上** |
| 2 | 举起右手，维持 **3 s 以上** |
| 3 | 抬起左腿，维持 **3 s 以上** |
| 4 | 抬起右腿，维持 **3 s 以上** |
| 5 | 举起双手，维持 **3 s 以上** |
| 6 | 左右摇头，维持 **3 s 以上** |

**7.3 —（二）评分 — 二维码项目**  
共 3 处二维码；每处**正确识别并完成指定动作**得 **20 分**（单场最多 60 分该项）。

**场地尺寸（与提前量估计相关）**  
场地 **3660 mm×2440 mm**；环形赛道全长约 **6140 mm**，赛道宽 **350 mm**（用于估算「离码多远仍应在视野内」）。

### 与当前固件的差距（工程判断，非规则条文）

- 规则要求 **3 次**扫码且每动作 **≥3 s**：**`OpenMV_flash/main.py` 已发 `MSG_QR_EVENT`（1～6）**；**动作时长与得分**仍须 **主控** 保证。  
- **`qr_uart_test.py`** 仅用于 **脱离巡线** 时的 UART/解码单测。

|------------------|------------|------------|

| **3 处**二维码（**5 cm×5 cm**；位置见规则图 1）；赛前抽 **3 张** 1–6 | **`main_webots_aligned` / `OpenMV_flash`** 已 **集成识别 + 协议事件**；**三处不同码**由当场抽签决定，固件侧每次稳定识别即发对应 **1～6** | **同一码重复触发**：依赖 **`qr_send_cooldown_ms`** 与主控去重；**丢线时不扫**（可配 `qr_only_when_tracking`） |

| 跨越 **红色包裹** 木条（10×20 mm，竖 20/平 10）；碰移木条则 **越障 0 分** | `main_webots_aligned` 里 **红块检测默认关**（灰度图，需 `red_detect_on_grayscale` 等才开）；Webots 侧重巡线 | **红色障碍与跨越策略**主要在本届仍是**步态/里程计**；视觉若要做「接近木条」辅助需单独开 **RGB 或的红启发** |
| **限宽门最窄 240 mm**（场地图注） | 未见独立「限宽门」视觉模块 | 若需：可能要 **额外 ROI/宽度检测** 或与线宽逻辑结合 |
| 使用传感器识别 **赛道、二维码、障碍物** 并闭环 | **赛道 + 二维码（主程序）**；**红条** 以步态为主、视觉默认可关 | 若要视觉辅助越障：需 **开红检测** 或加策略 |
| 比赛时间 **≤4 min**、准备 **≤1 min**、两轮取最好 | 无计时计分软件 | 队务/场边 |
| 行进速度分公式、二维码 **20×3**、越障 **60**、扣分/终局/零分条款 | 无自动算分 | 队务理解即可 |
| 资格认证 WORD、队名标识、QQ 群等 | 无 | 行政 |
| 机器人结构 **DOF≥13**、尺寸 **高<450 mm** 等 | 无 | 机械 |
| **禁止赛中无线/有线遥控**；程序 **赛前一次烧录**、裁判可要求重启 | 本仓库是 **本体自主 UART 协议**，不实现遥控 | 架构需队里自检合规 |
| 附加分：机械/电路**自主设计**与资料 | 无 | 队务 |

## 项目架构问题诊断（2026-05-11）

### 已修复
1. **两份巡线代码不同步**：`CVpart/main/main_webots_aligned.py` (1478行) 和 `Webots/controllers/line_follow_transfer/line_follow_transfer.py` (1918行) 实现同一算法但两套代码。Jetson 方案解决：`jetson_vision/` 模块仿真和真机共用。
2. **过时文件**：根目录 `line_follow.py` (763行孤本)、空目录 `docs/rules/`，已删除。
3. **规划文件散落**：`docs/project/` → 根目录，已迁移。

### OpenMV 硬件硬伤
4. **QR 检测物理瓶颈**：QQVGA (160×120) 下 5cm 码 40cm 高/45°倾角，有效检测距离 ≤50cm。不可逾越的像素限制。
5. **红条检测不可用**：OpenMV 灰度 sensor 下 `red_detect_on_grayscale` 默认关闭。规则要求跨红条。RGB565 可开但牺牲巡线帧率。
6. **转向量化为 4 个离散值**：go/left/right/slight_left，无法输出连续控制量。

### 需要确认
7. **`config/field/场地参数基线.json` 缺少 QR 槽位坐标**：`qr_slots` 为空数组。规则：3 个 QR 分别在起跑线后 30cm、直道中间、弯道中间。需赛道几何计算后填入。
8. **Webots Camera 高度 0.38m vs 参数 40cm**：相差 2cm，不影响功能但建议统一。

### Jetson Nano 优势
9. **16x 像素**：QQVGA 19K → 640×480=307K
10. **连续控制**：偏差 px → 转向角度 0.1° 精度
11. **同一代码舱**：`jetson_vision/` 模块在 Webots 和真机共用
